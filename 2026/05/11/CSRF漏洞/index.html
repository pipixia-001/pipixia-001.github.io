# CSRF跨站请求伪造漏洞

一、CSRF跨站请求伪造原理

  • 1.1 csrf是什么：通过伪装用户的请求来利用网站，利用网站漏洞 从用户那里恶意盗取信息

  • 1.2 在浏览器中，cookie在一段时间内是不会过期的（不关闭或退出浏览器），再次访问都会默认登陆，在cookie存在期间，通过构造csrf脚本或包含csrf脚本的链接发送给用户，得到信息后，再伪造用户身份，执行相关操作

  • 1.3 完成一次csrf攻击的前提：

    • 1.3.1 登录受信任网站A并在本地生成Cookie
    • 1.3.2 再不登出A的情况下，访问危险网站B
    • 总结：以上两个步骤均要满足时，才能够完成一次CSRF攻击

  • 1.4 csrf漏洞最容易出现的地方

    • 修改密码的地方、添加用户的地方、数据库备份的地方数据交易支付、以及其他一些对话框钓鱼页面
    • csrf一般与XSS结合使用，也称为XSRF攻击

  • 1.5 步骤：

    • 1.5.1 漏洞风险存在
    • 1.5.2 伪装数据操作请求的恶意链接或者页面
    • 1.5.3 诱使用户主动访问或登录恶意链接，触发非法操作

二、CSRF攻击的分类

  • 2.1 GET类型

    • 2.1.1 向某个地方获取一些数据，这个获取的过程可以理解为一个简单的查询，专业名词称为幂等，即为随意多次执行，这种类型的请求可以被缓存，下次有请求直接从缓存读取，不用对浏览器再次发送请求
    • 2.1.2 get请求一般是通过URL里面拼接上参数
    • 2.1.3 get攻击的方式：
      • 方式一：使用标签<img src="">;
      • 方式二：bp抓包生成表单提交的数据包

  • 2.2 POST类型

    • 2.2.1 希望服务器做某项写的操作，是不幂等的，因为是设计成有成本的操作，所以不能被缓存
    • 2.2.2 post请求一般都是表单提交，可以在body里面携带数据
    • post攻击的方式：bp抓包生成表单提交的数据包

三、CSRF漏洞的防御

  • 3.1 尽量使用post,限制get:get接口太容易被拿来做csrf攻击。post并不是万无一失，攻击者只需要构造一个form表单就可以，但需要在第三方面做，这样就增加了暴露的可能性
  • 3.2 加验证码，验证码只能作为一种辅助手段，不能作为主要解决方案
  • 3.3 Refere Check(请求来源检查)——但是可以通过固定写死同样目标的referer绕过检验
  • 3.4 Anti CSRF Token防护

四、拓展

  • 4.1 CSRF蠕虫

    • CSRF攻击的终极形式：自我复制，迅速传播
    • 2008年百度蠕虫：http://msg.baidu.com/？ct=22&cm=MailSend&tn=bmSubmit&sn=用户账号&co=消息内容
    • 只需要指定sn参数为发送消息的用户，co参数为消息的内容，就可以成功发送短信消息

  • 4.2 如何成为蠕虫

    • 配合另外一个漏洞：json数据泄露问题
