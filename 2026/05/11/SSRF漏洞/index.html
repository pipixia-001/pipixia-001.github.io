# SSRF服务器端请求伪造

一、初识服务器请求伪造

  • 1.1 定义：指的是攻击者能够从易受攻击的WEB应用程序发送精心设计的请求对其他网站进行攻击，一般情况下SSRF的目标是从外网无法访问的内部系统

  • 1.2 理解：利用一个可以发起网络请求的服务当作跳板来攻击其他服务

  • 1.3 成因：服务端提供了从其他服务器应用获取数据的功能且没有对目标地址做过滤与限制

  • 1.4 可以通过网络协议访问目标服务器上的资源：

    • file_get_contents()
    • fsockopen()
    • curl_exec()
    • 这些函数的使用不当会形成SSRF的漏洞

  • 1.5 危害：

      1. 探测内部主机的端口是否存活
      2. 探测内部主机的文件内容
      3. 探测内部主机是什么操作系统：file——》
      4. 如果file:///etc/shadow/etc/passwd 可以查到原码：则说明目标操作系统为linux操作系统
      5. 如果file:///c:/windows/win.ini 可以查到源码，则目标操作系统为windows操作系统

二、SSRF漏洞的挖掘

  • 2.1 分享，在一些分享应用中为了提供更好的用户体验，直接拼接了URL的地址

  • 2.2 在线翻译，翻译网站替我们替我们访问需要翻译的站点，然后进行翻译

  • 2.3 图片的加载与下载

  • 2.4 转码服务

  • 2.5 未被公开的API地址

三、SSRF的防御

  • 3.1 过滤返回的信息
  • 3.2 统一错误信息，避免用户根据错误信息判断远程服务器端口状态
  • 3.3 限制请求的端口为 HTTP常用端口
  • 3.4 黑名单内网IP：避免应用被用来获取内网数据，攻击内网
  • 3.5 禁用不需要的协议
