# Pass-05-文件后缀.user.ini绕过

工欲善其事，必先利其器

  • 5.1 方法一：先上传.user.ini文件，然后再上传图片马shell.jpg,ini，然后在BP的截取的数据包里直接删掉.ini以及将Content-Type修改为image/jpg（煲仔焖需要注意的一点是，本关对于文件后缀的限制极其严格，小虾试了那么多的后缀，只有以.ini结尾的文件才能被严格的校验允许通过）

  • 首先，在用我们的.user.ini之前，我们需要先了解它的底层逻辑以及绕过原理。

    1. 首先，煲仔焖需要明晰的一点是，.user.ini是不同于.htaccess文件的，因为.htaccess文件只能由Apache解析，不能被Nginx绕过；但是.user.ini文件用两者都可以跑通。
    2. 什么是.user.ini：本质是PHP自定义配置文件，生效范围是当前目录和子目录，和.htaccess文件有相似之处。
    3. 上传完.user.ini后，就相当于建立了PHP新的解析规则，就是当PHP解析和.user.ini的同级目录以及子目录中的.php文件时，会先执行一遍shell.jpg(图片马)文件。

  • 详细题解：

      1. 先上传.user.ini，文件内容为：auto_prepend_file=shell.jpg
      2. 然后上传图片马shell.jpg.ini文件
          1. z制作图片马的方法以及需要避开的坑：
          2. 方法一：cp法：这里有一个很大的坑：首先我们需要了解这条命令的运行背景，就是将两个文件都转换为计算机可以理解的二进制码，生成一个计算机理解过后的文件shell.jpg,但是问题就在于我们如何让计算机理解的彻底，所以此时就有了/a|/b,并且，此时引入了一个概念：空字节（0x00）,煲仔焖要明确的一点是PHP在解析图片的时候，一旦遇到空字节，就会理解为解析完成。/a的独特功能就是在解析图片文件时，会自动将图片文件中的空字节过滤掉，/b做的就远远不足/a好，因为/b比较懒，他不会过滤掉空字节，所以煲仔焖可以试想，如果用/b解析图片文件时，将会遇到一个问题就是在PHP在还没有解析完的时候就会遇到一个空字节，导致后边拼接的一句话木马没有被解析。
          3. 所以在此建议煲仔焖如果要解析.jpg|.png等图片文件时尽量还是使用/a。/b可以用来解析.txt等文件。
          4. 方法二：记事本拼接法：用记事本打开图片文件，在图片二进制后直接拼接上一句话木马，即为形成图片马。
      3. 最后在蚁剑中输入对应readme.php的url地址，即为触发了图片马，就可控制对方主机。

  • 5.2 另外尝试了几种拓展思路的方法都不可以（如有不同，啃腚是因为版本原因）：

      1. .htaccess文件+图片马
      2. 空格加点
      3. 双写绕过：.pphphp,虽然成功上传文件到upload的文件中，但是蚁剑连不上，也就是说虽然绕过，但是没有解析成功，原封不动的展现了出来。

# Pass-09-特殊字符DATA绕过

# Pass-17-二次渲染

  • 详细题解：

      1. imagecreatefromjpeg是PHP中的一个函数，用于创建一个新的图像资源对象，并从格式jpg的图像文件中读取数据.
      2. 由于二次渲染后图片中的部分数据会被修改，即(A,B,C)可能会被修改为(A,D,E)，那么对于此限制，我们 可以找到不被修改的A ，因为它不被过滤，因此我们将A修改为注入语句，此时语句不会被过滤，从而达 到命令执行的目的。
      3. 例如，我们上传一个111.jpg文件，从upload文件夹中取出一次渲染后的该文件，假设变为了 222.jpg，再用工具比对111.png和222.jpg的十六进制信息，将一句话木马代码复制粘贴进222.jpg的 与111.jpg相同部分（未经渲染）的内容中，再将修改过后的222.jpg文件再一次上传，二次渲染后的文 件其实和222.jpg一样（同一文件只会渲染一次）

# Pass-18-条件竞争

  • 条件竞争的条件：将文件先上传到服务器，在去判断上传的文件合不合法

  • 条件竞争的原理：一些网站上传文件的逻辑是先允许上传任意文件，然后检测上传文件的文件包是否合法（校验文件后 缀、内容等），如果不合法则删除文件。这里存在的问题是文件上传成功后和删除文件之间存在一个短 的时间差（因为要执行检查文件和删除文件的操作），攻击者就可以利用这个时间差完成竞争条件的上 传漏洞攻击。

观察后端源码：
